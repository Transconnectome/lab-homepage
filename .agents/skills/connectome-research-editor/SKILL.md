# Connectome Research Editor

## 필수 지침과 범위

저장소 루트를 확인한 뒤 루트 기준 `docs/research-editorial-guidelines.md`를 처음부터 끝까지 읽고 적용한다. 적용되는 `AGENTS.md`, `README.md`, 기존 운영 문서도 확인한다. 이 스킬은 상세 지침의 요약본이 아니라 해당 절차로 연결하는 진입점이다.

현재 요청이 연구 소개의 실제 개편인지, 일부 주장 검토인지, 지침 설치만인지 먼저 구분하고 그 범위 안에서 작업한다. 단순히 스킬이 선택되었다는 이유로 전체 홈페이지를 개편하지 않는다.

## 실행 절차

1. **현재 상태 파악:** `git status`, 콘텐츠 컬렉션·스키마, 공통 페이지 컴포넌트, 언어별 라우트, 자동 동기화 경로를 확인한다. 기존 작업을 보존한다.
2. **진단:** 해당 범위에서 자료 부족 / 설명 부족 / 구조 문제를 구분한다. 실제 문장·파일 위치와 개선 우선순위를 기록한다.
3. **근거 확보:** 허용된 원자료를 읽고 주장–출처–연구설계–결과–해석 범위–한계를 연결한다. 연구실과 논문의 관계, 출판본·프리프린트·연구 계획을 구분한다. 읽지 못한 범위는 명시한다.
4. **집필과 검토:** 질문, 지식의 빈틈, 접근의 이유, 실제 기여, 사례, 한계, 다음 질문, 다른 연구와의 연결을 설명한다. 상세 지침의 품질 기준을 적용하고 분야별 검토·수정은 최대 두 차례 수행한다. 입증되지 않은 주장은 삭제하거나 범위를 좁힌다.
5. **구현:** 확인된 내용부터 짧은 소개 → 개요 → 상세 페이지로 반영한다. 기존 기술 스택·디자인·한국어 루트와 영어 `/en/` 경로를 유지한다. 검토만 요청받았다면 코드는 수정하지 않는다.
6. **검증:** 현재 프로젝트에 존재하는 빌드·테스트와 사용 가능한 브라우저 도구로 확인한다. 실제 사용하지 않은 도구·스킬·서브에이전트나 실행하지 않은 검증을 보고하지 않는다.
7. **인계:** 공개 가능한 근거와 검토 기록은 루트 기준 `docs/research-content-review.md`에 누적하되 기존 기록을 덮어쓰지 않는다. 변경 파일, 대표 수정 전후, 검증 결과, 남은 공개·공식 입장 판단을 보고한다.

전체 개편 요청에서는 중요하고 근거가 충분한 분야 하나를 먼저 완성하여 품질 기준으로 삼고, 같은 절차를 나머지 분야로 확장한다. 단일 분야 요청에서는 관련 없는 분야까지 넓히지 않는다.

## 역할과 안전 경계

메인 에이전트만 사이트 파일을 수정한다. 실제 서브에이전트를 사용할 수 있으면 근거 조사자와 비판적 검토자에게 최대 두 명까지 읽기 중심으로 위임한다. 사용할 수 없으면 순차 수행하고 독립 검토를 받았다고 쓰지 않는다.

출처 개수나 높은 자기평가 점수로 품질을 대체하지 않는다. 비공개 원자료와 개인정보는 홈페이지뿐 아니라 공개 PR·검토 기록에도 포함하지 않는다. 공개 여부가 불명확한 항목은 제외하고 나머지 확인 가능한 작업을 진행한다.

사용자 승인 없는 원격 push, PR 병합, 운영 배포, 워크플로·도메인 변경, 유료 서비스 가입은 하지 않는다. 지침 등록과 실제 본문 개편, 검증과 운영 배포를 명확히 구분한다.

## 사용 예

```text
connectome-research-editor를 적용해 연구 소개의 부족함을 진단하고,
근거 조사·비판적 검토를 거쳐 실제 로컬 페이지를 개선하라.
중요하고 근거가 충분한 분야 하나부터 완성한 뒤 나머지로 확장하라.
기존 로컬 변경사항을 보존하고 운영 배포는 하지 말라.
```
