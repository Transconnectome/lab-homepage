# 홈페이지 "AI가 만든 티" 진단과 개선 방향

작성일: 2026-09-11 · 대상: `main` 기준 현재 사이트(www.connectomelab.com) · 방법: 전 페이지 소스 검토 + 데스크톱(1440px)/모바일(390px) 전 페이지 스크린샷 육안 검수

이 문서는 진단과 방향만 담는다. 코드는 바꾸지 않았다.

---

## 1. 결론 한 줄

"AI 티"는 색이나 폰트에서 나지 않는다. **(a) 모든 것을 똑같은 카드 격자에 넣는 구조, (b) 광고 카피처럼 다듬어진 문장, (c) AI 기능을 전면에 내세운 인터페이스(챗 버블·모델명 칩·레이더/아이디어 메뉴)** 세 가지에서 난다. 팔레트(종이색 + 청록), 마루부리/프리텐다드 타이포, 실제 구성원 사진은 이미 좋은 자산이라 그대로 두면 된다.

---

## 2. 어디에서 티가 나는가 (증거)

### 2-1. 구조: "카드 격자 8연타" 홈페이지

홈 한 페이지가 데스크톱에서 5,782px. 여덟 개 섹션이 전부 같은 리듬으로 반복된다.

```
소제목(eyebrow) → 세리프 큰 제목 → 설명 한 줄 → 흰 카드 2~3열 격자 → "전체 보기 →"
```

- `card`/`card-hover` 클래스 사용 20곳, `rounded-2xl` 흰 카드가 사이트 전체의 유일한 컨테이너다. 뉴스·프로젝트·연구 분야·논문·동문·합류 CTA·심지어 합류 페이지의 "지원 방법" 본문까지 카드다.
- 모든 카드가 hover 시 같은 방식(-0.5px 올라감 + 그림자)으로 반응한다. 이것이 Tailwind UI 템플릿 특유의 질감이다.
- 연구 분야 4개를 3열 격자에 넣어 마지막 카드 하나가 혼자 남는다(홈 "파운데이션 모델부터 경외의 신경과학까지" 섹션). 격자가 내용에 맞춰진 것이 아니라 내용이 격자에 맞춰졌다는 신호다.
- 페이지마다 동일한 헤더 블록(`max-w-2xl` eyebrow + h1 + 설명문)으로 시작한다. 연구·구성원·논문·소식·레이더·아이디어·합류 7페이지가 첫 화면에서 구분되지 않는다.

### 2-2. 문장: 카피라이터의 목소리, 연구자의 목소리가 아님

`src/i18n/ui.ts` 기준 줄표(—) 32회, 화살표(→) 10회. 아래 패턴이 반복된다.

| 패턴 | 예 (현재) |
|---|---|
| 수사적 질문 | "뇌가 궁금한가요, 모델이 궁금한가요 — 아니면 둘 다인가요?", "AI라면 다음에 무엇을 시도해 보자고 할까?" |
| "X부터 Y까지" | "파운데이션 모델부터 경외의 신경과학까지" |
| "A, B, C, 그리고 D까지" 열거 | "심리학자와 엔지니어, 물리학자, 경제학도, 그리고 미술사학도까지" |
| 대구법 슬로건 | "연구는 치열하게, 꿈은 대담하게, 삶은 즐겁게", "갈래는 달라도 질문은 하나" |
| 줄표로 이어붙인 여운 | "— 그것을 가려내는 것이 재미의 절반입니다", "— 창의성은 삶의 즐거움에서 자란다고 믿습니다" |
| 자기 설명 | "— 레오나르도 다빈치. 커넥톰 연구실의 출발점이 된 믿음입니다." (모토 아래에 모토를 해설) |
| 메타 고백 | "정직성 안내:", "큐레이션된 FAQ — 실시간 AI가 아닙니다" |
| 모든 카드 끝의 "자세히 보기 →" | 홈 연구 카드 4개, 섹션 링크 5개 |

문장 하나하나는 나쁘지 않다. 문제는 **모든 문장이 같은 정도로 다듬어져 있다**는 것이다. 사람이 쓴 사이트는 어떤 문장은 무뚝뚝하고 어떤 문장은 길다. 균질한 세련됨 자체가 기계 냄새다.

### 2-3. 인터페이스: AI 기능이 사이트의 얼굴이 됨

- **우하단 떠 있는 챗 버블**("Lab guide · 연구실 안내")이 전 페이지에 있다. 2024년 이후 "AI로 만든 사이트"의 가장 강한 시각 신호다. 내용은 정적 FAQ 7개라서 굳이 대화형 UI일 이유가 없다.
- 주 메뉴 6개 중 2개(레이더, 아이디어)가 LLM 파이프라인 산출물이다. 사이트의 1/3이 "AI가 만든 것"을 보여주는 데 쓰인다.
- 홈 "주요 프로젝트" 카드마다 `🤖 claude-fable-5` 칩, 아이디어 카드마다 `google/gemini-2.5-flash` 칩이 붙는다. 출처 표기는 옳지만 **홈 첫 화면에 모델명이 노출되는 것**은 방문자에게 "이 사이트는 AI가 채웠다"고 말하는 셈이다.
- 칩 안의 이모지(🤖 ✨ 🧠 ⚡ 🎓 🎨), 라운드 필(pill) 탭 필터(전체/지도교수/대학원생…, 전체/fMRI 파운데이션 모델/…), 모노스페이스 카운터("13건 · arXiv에서 매주 갱신", "N / M"), BibTeX 복사 시 컨페티. 모두 SaaS 대시보드 어휘다.
- 청록 각진 버튼(`rounded-lg bg-lab-700`) 7곳. 네비게이션·히어로·합류·아이디어·구성원 탭에 같은 버튼이 있어 어디가 진짜 행동 유도인지 구분되지 않는다.

### 2-4. 시각: 실물이 없다

- 홈에 **사진이 0장**이다. 구성원 사진 34장이 `public/assets/members/`에 있고 퀄리티도 좋은데 홈에서는 이름 칩("이아현 → 서울대학교 뇌인지과학과 박사과정")으로만 등장한다.
- 홈에 실제 연구 그림(fMRI 지도, EEG 파형, 커넥톰 행렬)이 하나도 없다. 대신 일러스트라고 명시한 3D 점구름이 있다. "진짜 데이터가 없어서 만든 그림"으로 읽힌다.
- 해커톤, 옵/신 전시, 리트릿은 문장으로만 존재한다. 구 Google Sites에는 사진이 있었다.

## 3. 유지할 것

- 종이색 바탕 + 잉크 + 청록 단일 액센트 팔레트
- 마루부리(한글 디스플레이)·Hahmlet(라틴)·프리텐다드·Plex Mono 타이포 시스템과 `:lang(ko)` 보정 규칙
- 한국어 루트 / 영어 `/en/` 라우팅, 콘텐츠 컬렉션 구조
- 구성원 사진과 `passions` 데이터
- 3D 연구 지도(위치만 낮춘다)
- 접근성 작업(대비, 포커스, reduced-motion)

## 4. 방향: "브로셔"에서 "연구실 게시판"으로

사람이 만든 연구실 사이트는 대개 **짧고, 날짜가 있고, 비대칭이고, 한 군데는 투박하다.** 다음 다섯 축으로 바꾼다.

### 4-1. 홈을 세 막으로 줄인다 (현재 8섹션 → 3)

1. **한 문장 + 진짜 이미지 하나.** 헤드라인은 다빈치 문장 그대로 두되 해설 문장을 지운다. 옆에는 단체사진 또는 실제 연구 그림(예: SwiFT 4D 활성 지도, DIVER 전극 배치도). 버튼은 하나("연구 보기")만.
2. **지금 일어나는 일.** 소식 3건 + 최근 논문 3편을 **카드 없는 목록**(날짜 · 제목 · 한 줄)으로. 신문 1면의 단신처럼.
3. **사람과 합류.** 구성원 사진 스트립(얼굴 8~12장) + "함께하기" 링크 한 줄. 동문 진로는 구성원 페이지로 이동.

3D 지도는 홈 하단 또는 연구 페이지 상단으로 내린다. 프로젝트·논문 격자는 각 페이지로 보낸다.

### 4-2. 카드 격자를 목록·괘선·비대칭 레이아웃으로

- `card` 사용을 사이트 전체에서 3~4곳 이하로 줄인다. 나머지는 상단 괘선(`border-t`) + 여백으로 구분.
- 논문 목록은 연도별 헤딩 아래 줄글 목록(저자. 제목. 학술지. 연도.)으로. 필터는 텍스트 링크 한 줄로.
- 연구 4개 분야는 격자가 아니라 **번호 붙은 세로 목차**(01 Neuro-X / 02 … )로.
- hover 시 올라가는 애니메이션·그림자 제거. 링크 hover는 밑줄만.
- 2/3 + 1/3 같은 비대칭 열을 한 페이지에 한 번은 쓴다. 전면(full-bleed) 사진 한 장을 한 페이지에 한 번은 쓴다.

### 4-3. 문장을 연구자 목소리로 다시 쓴다

원칙: 줄표·화살표·수사적 질문·"X부터 Y까지"·대구법 슬로건 제거. 구체적 명사와 숫자, 연도, 사람 이름을 넣는다. 일부 문장은 의도적으로 짧고 사실적으로 둔다.

| 위치 | 현재 | 제안 |
|---|---|---|
| 홈 모토 해설 | "— 레오나르도 다빈치. 커넥톰 연구실의 출발점이 된 믿음입니다." | (삭제. 각주로 "Leonardo da Vinci"만) |
| 홈 소개 | "뇌의 연결이 어떻게 마음을 만들어내는지 연구합니다. 인지와 정서, 발달, 그리고 정신건강의 회복탄력성까지가 그 대상입니다. 뇌 파운데이션 모델과 멀티모달 유전체학, 양자 머신러닝이 우리의 도구이며, ‘잘 보는 것’이야말로 과학적 능력이라 믿습니다." | "서울대 심리학과에 있는 뇌영상·유전체·머신러닝 연구실입니다. 수만 명 규모의 fMRI와 EEG로 뇌 파운데이션 모델을 만들고, 그 모델로 아동·청소년의 정신건강 발달을 예측하는 일을 합니다. 2019년 시작했고 현재 대학원생 20여 명이 있습니다." (숫자는 확인 후 기입) |
| 홈 연구 섹션 제목 | "파운데이션 모델부터 경외의 신경과학까지" | "연구 분야" |
| 홈 합류 CTA | "뇌가 궁금한가요, 모델이 궁금한가요 — 아니면 둘 다인가요?" | "대학원생과 인턴을 상시 모집합니다." |
| 구성원 제목 | "모델 뒤에 있는 사람들" | "구성원" |
| 구성원 설명 | "심리학자와 엔지니어, 물리학자, 경제학도, 그리고 미술사학도까지. 좋은 과학에는 여러 개의 시선이 필요하다고 믿는 서울대학교 연구팀입니다." | "교수 1명, 대학원생 N명, 학부 인턴 N명, 스태프 1명. 심리학·컴퓨터공학·물리학·경제학·미술사 전공자가 섞여 있습니다." |
| 아이디어 페이지 | "정직성 안내: 아래 내용은 전부 기계가 생성한 것이며 …" | 페이지 하단 각주 한 줄: "이 페이지의 가설은 매주 Gemini가 생성하며 연구실이 검토하지 않았습니다." |
| 카드 하단 | "자세히 보기 →" | (삭제. 제목 자체가 링크) |
| 레이더 제목 | "이번 주 우리가 읽고 있는 것" | "읽는 중" 또는 "arXiv 주간 스캔" |

가장 효과가 큰 한 가지: **PI가 직접 쓴 200자 소개**를 홈 첫 화면에 넣는 것. 교정하지 말고 그대로 싣는다. 그 문단 하나가 어떤 CSS보다 "사람이 있다"는 신호를 낸다.

### 4-4. AI 흔적을 뒤로 보낸다 (지우는 것이 아니라 자리를 바꾼다)

- **챗 버블 제거.** FAQ 7개는 합류 페이지의 "자주 묻는 질문" 아코디언 또는 단순 목록으로. 출처 표기 문구("실시간 AI가 아닙니다")도 함께 사라진다.
- **레이더·아이디어를 주 메뉴에서 빼고** 소식 페이지 하단 또는 푸터의 "실험실 노트" 묶음으로. 두 페이지를 하나("읽고 생각하는 것")로 합치는 것도 가능.
- **모델명 칩은 홈에서 제거**, 각 상세 카드 하단 작은 회색 텍스트로만 유지("요약: gemini-2.5-flash"). 출처 정직성은 지키되 첫인상에서는 빼는 것.
- 칩의 이모지 전부 제거. 필터 필(pill) → 밑줄 텍스트 링크 또는 `<select>`. 컨페티 제거. 모노스페이스는 논문 ID·DOI·날짜에만.
- 청록 채움 버튼은 사이트 전체에서 2곳(네비 "함께하기", 합류 페이지 이메일)만 남기고 나머지는 텍스트 링크로.

### 4-5. 실물을 넣는다

- 홈 히어로: 단체사진(홍천 리트릿) 또는 EEG 아트 전시 사진. 없다면 실제 논문 그림 한 장(라이선스 확인 후).
- 소식 항목마다 사진 1장을 목표로 한다(현재 6건 중 1건만 이미지).
- 구성원 페이지 상단에 작업실·화이트보드·서버실 같은 현장 사진 1~2장.
- OG 이미지도 현재 로고 기반이라면 사진으로.

사진은 사용자 준비가 필요하다. 그 전까지는 사진 자리에 회색 박스를 두지 말고 레이아웃 자체를 사진 없는 버전으로 만든다(빈 자리는 더 티가 난다).

## 5. 작업 순서 제안

| 단계 | 내용 | 규모 | 효과 |
|---|---|---|---|
| A | 챗 버블 제거 → FAQ 섹션 이관, 홈 모델명 칩·이모지·컨페티 제거, 레이더/아이디어 메뉴 강등 | 반나절 | 크다. 코드만으로 가능 |
| B | 문구 전면 재작성(`ui.ts` + 페이지 헤더). PI 소개문 수령 | 1일 + PI 시간 | 매우 크다 |
| C | 홈 3막 재구성, 카드 → 목록·괘선, hover 애니메이션 제거, 버튼 2곳으로 축소 | 1~2일 | 크다 |
| D | 논문·구성원 페이지 필터 UI 단순화, 연구 페이지 목차형 재배치 | 1일 | 중간 |
| E | 사진 수집·배치, OG 이미지 | 사용자 준비 후 | 크다 |

A와 B만 해도 인상이 달라진다. C부터는 디자인 판단이 들어가므로 A·B 결과를 보고 결정하는 것이 낫다.

## 6. 결정이 필요한 질문

사이트를 고치기 전에 답이 있어야 방향이 정해지는 질문들이다.

1. **첫 방문자 한 사람을 고르면 누구인가?** 연구실을 고르는 서울대 학부 4학년인가, 논문을 심사하는 보스턴의 교수인가, 자녀 연구 참여를 고민하는 학부모인가. 지금 홈은 셋 모두에게 말하려다 누구에게도 말하지 못한다.
2. **이 연구실만 보여줄 수 있는 이미지 한 장은 무엇인가?** 홍천 해커톤의 새벽 사진, 옵/신 전시장의 EEG 아트, 5만 명 fMRI를 한 장에 그린 그림. 그 한 장이 정해지면 홈 첫 화면 디자인은 거의 끝난다.
3. **레이더와 아이디어 랩은 대외용인가, 내부 도구인가?** 대외용이면 "연구실이 만든 도구"로 소개해야 하고, 내부용이면 메뉴에서 빠져야 한다. 지금은 둘 사이에 있다.
4. **PI가 200자를 직접 쓸 수 있는가?** 가능하면 B단계의 절반이 해결된다.
5. **홈페이지가 "브로셔"여야 하는가, "날짜가 찍힌 게시판"이어야 하는가?** 후자라면 홈 첫 화면에 "2026년 9월" 같은 날짜가 보여야 하고, 소식이 자주 갱신되어야 한다. 갱신 주기를 감당할 수 있는지가 관건이다.

### 조금 엉뚱한 질문

- 이 사이트를 **A4 한 장짜리 인쇄 뉴스레터**로 만든다면 무엇이 남는가? 남는 것만 홈에 두면 된다.
- **구성원 페이지가 홈이라면** 어떨까. 사진 34장이 첫 화면인 연구실 사이트는 드물고, 이 연구실은 그럴 자산이 있다.
- 논문 목록을 **연도가 아니라 "질문"으로** 묶으면 어떤 목차가 나오는가? 그 목차가 곧 연구 페이지의 구조다.
- 3D 지도를 지우고 대신 **PI가 손으로 그린 연구 지도 스캔**을 올리면 사이트의 인상은 어떻게 달라질까?
- 사이트에서 **가장 못생겨도 되는 곳**은 어디인가? 한 군데는 투박해야 사람이 만든 것으로 보인다.
